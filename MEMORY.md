- For Bash scripting, prefer NOT to use global safety flags like `set -e`, `set -u`, `set -o pipefail`, and `set -o nounset` in scripts that source third-party profiles (e.g., conda/mamba) or run in interactive sessions. Modern Bash practices suggest these flags obfuscate errors, trigger unbound-variable failures on third-party code, and terminate active terminal sessions suddenly. Enforce safety via explicit manual checks (e.g., `command || { log_err "Failed"; exit 1; }`) and local traps instead.
- Use `bash -n` and `shellcheck` to verify bash scripts.
- Always use the dedicated `unlink` utility instead of `rm` or `rm -f` when removing symbolic links to ensure safe detachment of the reference without risking modifications to their targets.
- For temporary files and downloads, avoid using static paths under `/tmp` (e.g., `/tmp/installer.sh`), as this causes write permission denials and clashes on multi-user/HPC environments if another user has already run the script. Instead, use `mktemp` to generate secure, uniquely named temporary file paths (e.g., `mktemp "/tmp/installer-XXXXXX.sh"`).
- For Git commit messages, prefer the `caveman-commit` standard: ultra-compressed, exact, conventional commits format, focusing on "why" over "what" with a terse subject (≤50 characters).
- Default the Gemini CLI to newer models natively (like `gemini-3.5-flash`) at startup. To bypass default project-level preview access checks and fallback routes, configure `settings.json` with `"experimental": { "dynamicModelConfiguration": true }` and empty resolution contexts under `"modelConfigs"`.
- Never run git commands that modify the repository (e.g., `git add`, `git commit`, `git merge`) automatically or unprompted. Instead, formulate the precise commands and present them as copy-pasteable blocks for the developer to review and execute themselves. Read-only commands like `git log`, `git status`, or `git diff` are permitted for safe research.
- Always update the project's context vault (e.g., ACTIVE_CONTEXT.md, SESSION_STATE.md, TODO.md) to log achievements and current state before preparing and presenting a commit.
